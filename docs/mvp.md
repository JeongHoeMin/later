# Later 첫 MVP 범위와 진행 상태

확인일: 2026-10-06. 현재 `main`의 `9394c1c`와 Task 검증 기록을 기준으로 정리했다. 사용자 결정으로 **장소 액션과 구독을 첫 MVP에 포함**한다. 기획 문서 정리는 완료했고 남은 설계/결정/구현은 후속 Task로 이관했다. 이 문서의 계획은 구현된 정책을 뜻하지 않는다.


## 논의 우선순위 변경: 구독 상세 설계 보류

사용자 결정(2026-10-06): 지금까지 합의한 상품 표·보관/만료/삭제 정책은 유지한다. **구독 시스템 관련 상세 설계와 추가 논의는 구독 기능 개발 시점까지 보류**한다. 월 분석 지급일·이월·추가권 유효기간/소비 순서·동시 구독 분석량·즉시 취소 일부 환불/사용량·결제 실패/복원/이벤트 동기화 등은 확정하지 않는다. 기존 원가 문서의 제안은 승인된 정책으로 승격하지 않는다. 구독의 첫 MVP 포함 결정을 취소하거나 구현 완료로 기록하는 것이 아니다.

다음 논의는 콘텐츠를 어떤 기준으로 나누고 화면·검색에 사용할 것인지다. 기존 기획의 주제 카테고리(맛집/데이트 등), 대상 정보(장소/제품 등), 출처/형식을 구분하는 방향부터 검토한다. 아래 결정 목록과 과거 Next Action의 구독 관련 확인 대기는 이 보류 결정에 의해 연기된다.

## 목표와 범위

Android/iOS에서 공유한 URL을 저장하고, 자동 분석된 내용을 자연어로 다시 찾으며, 장소 콘텐츠는 지도에서 열 수 있다. 무료 이용과 유료 구독에 따른 보관 권한을 제공한다.

첫 MVP에는 소셜 인증, URL 공유·저장, 목록·상세·삭제·원문 열기, 비동기 본문/메타데이터 분석, 요약·태그·카테고리·장소 추출, 임베딩·사용자 한정 검색, 네이버 지도 액션, 구독 및 보관 생명주기를 포함한다. 지원 사이트·분석 품질·과금·보관 정책의 상세 조건은 아래 결정 목록에서 확정한다.

OCR·개인 텍스트 저장, 공동 컬렉션·친구/팔로우, 자동 컬렉션, 재발견 알림, 브라우저 확장, 가격 추적, 상품·일정 액션은 기존 기획의 확장 후보이며 첫 MVP 포함 여부를 추가로 승인받기 전에는 구현 범위에 넣지 않는다. 만료 안내는 구독·보관 기능에 필요한 안내로 별도 정의한다.

## 상태 판정

- **완료:** 현재 코드에 기능이 있으며 관련 Task의 자동 검증 기록이 있다. 운영 배포나 실제 기기 검증 완료를 뜻하지 않는다.
- **부분 구현:** 화면·PoC 등 일부만 있고 사용자 흐름이 연결되지 않았다.
- **미구현:** 현재 코드에 해당 흐름이 없다.
- **확인 필요:** 정책 또는 실계정·실기기·운영 검증의 증거가 부족하다.

Task의 `phase: completed`만으로 완료를 판정하지 않는다. `status: cancelled`인 모바일 인증 API·세션 Task는 취소 이력이며 완료 기능에서 제외한다. 이 문서는 MVP 관점의 요약이고 개별 개발 Task의 상태 원본은 [.agent/tasks](../.agent/tasks/README.md)다.

## 첫 출시의 완료 기준

1. Android/iOS에서 실제 계정 로그인 후 공유한 URL이 서버에 저장되고, 앱 재시작 후 목록·상세·원문 접근이 가능하다.
2. 저장은 분석 완료를 기다리지 않는다. 분석 상태와 실패를 표시한다. 실패 항목을 유지/폐기할지는 사용자 보류 사항이므로 확정 후 완료 기준에 추가한다.
3. 합의한 지원 콘텐츠·평가 질의로 자연어 검색 품질을 확인한다. 목록·상세·검색·삭제 모두 다른 회원 데이터를 노출하지 않는다.
4. 장소가 있는 콘텐츠에서 지도 액션이 동작한다. 낮은 신뢰도 결과는 좌표나 특정 장소를 확정한 것처럼 표시하지 않는다.
5. 실제 테스트 결제 환경에서 구매·복원·갱신·취소·기간 종료·환불에 따른 권한을 확인한다. 클라이언트 표시만으로 Plus를 부여하지 않는다.
6. 만료 즉시 화면·검색 결과와 무료 개수 집계에서 제외하고, 만료 후90일이 지나면 사용자 연결을 자동 삭제한다. 제한 해제 구독 시 유예 중인 연결을 복구한다. 공통 Content/AI 분석은 연결 삭제와 분리해 보존하고, 사용자 연결이 없는 상태가180일 지속될 때 자동 영구 삭제한다. 시간 경계·복구/정리 경합·다른 회원 참조 보호를 검증한다. 구독 종료로 만료되는 경우 종료 시각+90일에 연결을 삭제한다.
7. 정책 변경 전 저장물에는 이전 정책, 변경 후 저장물에는 신규 정책을 적용한다. 기존 항목의 정책·만료일을 새 정책으로 일괄 변경하지 않는다. 신규 저장 시 정책 버전과 관계없이 전체 미만료 보관량을 현재 한도와 비교한다. 한도 이상이면 저장을 거부하고 기존 항목은 유지한다. 변경 전후 저장 및 조회·화면 표시, 한도 직전/도달/초과와 동시 저장을 검증한다.
8. 자동 테스트, 비결정론적 분석/검색 품질 평가, 실제 기기/외부 연동 검증, 운영 적용 여부를 각각 기록한다. 미확인 항목을 완료로 올리지 않는다.

## 독립 정책과 조합 기준 — 현재 결정 요약

사용자 요청에 따라 보관량(C), 보관기간(T), AI 분석 사용(A)을 독립적으로 관리한다. 아래 표는 기존 대화의 현재 결정 요약이다. 뒤의 상황별 상세/과거 제안은 이 요약과 최신 사용자 승인에 맞춰 해석한다. 실제 처리 순서·트랜잭션/API 설계를 확정한 것은 아니다. 구독 시스템 상세는 계속 보류한다.

### C: 보관량 기준

- 집계 단위는 사용자별 활성 보관 연결이다. 공통 Content 수나 다른 사용자 저장 수는 합산하지 않는다.
- 미만료 항목을 집계한다. 만료되어 숨긴 항목은90일 삭제 유예 중에도 활성 보관량에서 제외한다.
- 신규 사용자 연결 생성/만료 항목 복구는 활성 개수가 현재 한도 미만일 때만 허용한다. 한도 도달 시 차단하고 알림을 표시한다.
- 같은 사용자의 미만료 동일 콘텐츠 재저장은 중복 항목을 만들지 않는다. 개수 증분은0이지만 한도 도달 때 날짜 갱신까지 허용할지는 미확정이다.
- 운영 정책의 한도 감소는 기존 항목을 유지하고 신규 저장을 제한한다. 구독 종료/다운그레이드의 최신 N개 유지 규칙과 구분한다.

### T: 보관기간 기준

- 저장 정책 버전/조건을 사용자 연결에 기록한다. 새 정책은 이후 저장에 적용하고 재저장하지 않은 기존 항목의 조건은 유지한다.
- 사용자 명시적 재저장 성공 시 저장일을 갱신하고 현행 정책으로 만료일/조건 스냅샷을 갱신한다. 통신 재시도는 별도 재저장이 아니다.
- 만료 시 화면/검색에서 숨긴다. 현재 만료 시각+90일에 사용자 연결을 자동 삭제한다.
- 만료 유예 연결 재저장 복구 성공 시 이전 삭제 예약을 취소한다. 다시 만료되면 새 만료 시각+90일을 적용한다.
- 무제한 기간은 구독 중에만 적용한다. 종료 시 저장일 기준30일을 즉시 판정한다. 이로 인해 그 시점에 만료되면 종료 시각+90일에 연결을 삭제한다.
- 직접 삭제는 경고/확인 후 사용자 연결 즉시 삭제한다. 공통 콘텐츠는 모든 연결이 사라진 시점부터 연속180일 무연결이면 영구 삭제한다.
- 하루는24시간, 표시 기준은 기존 확정30일/24시간/1시간 경계를 따른다. 연결 삭제와 공통 콘텐츠 정리는 기간 생명주기이며 AI 분석량 소진으로 실행하지 않는다.

### A: AI 분석 사용 기준

- 유형 분류와 별도로 AI 필요 여부를 판단한다. 검증된 기존 분석 재사용 또는 충분한 구조화 정보 직접 추출이면 신규 AI 분석량을 사용하지 않는다.
- 의미 해석에 새 AI 분석이 필요한 경우에만 분석량을 사용한다. 해당 잔량이 없으면 이 신규 분석 저장 경로를 차단한다.
- 분석량 소진 자체로 기존 보관 항목을 만료/삭제하거나 기존 검색을 차단하지 않는다. AI 불필요 저장은 C/T 조건을 충족하면 가능하다.
- 월 제공량/가입 보너스/추가권 가격·수량은 확정 상품 표를 따른다. 지급일/이월/유효기간/환불 및 차감 시점·실패 차감 상세는 보류된 구독/분석 설계와 함께 구체화한다.
- 재시도/동일 요청 중복으로 분석량을 중복 차감하지 않는 방향이다. 검색 임베딩 비용과 콘텐츠 AI 분석권은 별도 개념이다.

## 확정 사항과 대화할 결정

확정: 첫 MVP에 장소 액션과 구독 포함. 서버·모바일 기능 분리 기록. 이미 완료된 기능은 근거와 함께 완료 표시. 모호한 사항은 사용자 대화로 확정.

### 무료 보관 정책과 변경 원칙 — 사용자 확정, 미구현

- 초기 Free 정책은 **100개와 저장 후 30일을 모두 적용**한다. 보관량이 현재 한도 이상이면 신규 저장을 거부한다. 새 저장 공간을 만들기 위해 오래된 항목을 자동 만료시키지 않는다. 기간 만료는 항목의 기존 정책대로 진행한다.
- 개수·기간 정책은 제품 배포 없이 변경할 수 있도록 서버가 정책 버전과 적용 시작 시각을 관리하는 방향으로 설계한다. 활성화 방법·관리 권한은 상세 설계에서 정한다.
- 새 정책은 변경 이후 새로 저장되는 항목부터 적용한다. 기존 저장 항목은 저장 당시 정책을 유지한다. 정책 변경만으로 기존 항목의 기간을 줄이거나 늘리지 않는다.
- 저장 항목은 저장 당시 정책 버전과 100개/30일 같은 조건의 스냅샷을 보존한다. 기존 정책 버전은 수정하지 않고 새 버전을 발행한다. 서버가 저장을 확정하는 시점에 정책을 선택하는 방향을 제안하며, 오프라인 수신 시점·재시도·중복 저장의 기준은 DISC-007에서 확정한다.
- 기간 제한은 항목에 적용된 보관 일수로 만료일을 산정한다. 예: V1 100개/30일에서 V2 50개/14일로 바뀌어도 V1 항목은 기존 30일을 유지하고 V2 항목부터 14일을 적용한다. V2 수치는 설명을 위한 예시이며 확정 정책이 아니다.
- 개수 제한은 **정책 버전별로 따로 세지 않고 전체 미만료 보관량**으로 신규 저장을 판정한다. 현재 Free 한도 미만일 때만 새 항목을 저장한다. 현재 한도 이상이면 기존 항목은 유지하고 신규 저장을 거부한다. ACTIVE/EXPIRING은 집계에 포함하고 EXPIRED와 연결 삭제 항목은 제외한다. 기간 만료 시 물리 삭제를 기다리지 않고 공간이 생긴다. 분석 실패/진행 상태와 보관 만료 상태는 별개다.
- 예: 한도가 100개에서 50개로 바뀔 때 기존 항목이 80개라면 80개를 기존 기간 조건대로 유지한다. 보관량 50개에서도 신규 저장은 거부하고, 49개가 되면 1개를 저장할 수 있다. 신규 저장으로 기존 항목을 밀어내지 않는다. 이 50개는 설명을 위한 예시다.
- 서버는 한도 판정과 항목 생성을 원자적으로 처리하여 동시에 요청해도 한도를 넘지 않게 한다. 거부 응답은 저장 성공으로 표시하지 않고 현재 보관량·한도·거부 이유를 모바일이 안내할 수 있게 제공한다. 구체적인 오류 계약은 상세 설계에서 정한다.
- 구독 가입·종료·재구독은 일반적인 Free 정책 변경과 구분한다. 구독 권한 종료로 항목이 만료되는 경우 만료 시각은 권한 종료 시각이며, 연결 삭제 예정일은 그 시각+90일이다. 과거 저장일+무료 보관일수로 삭제 기한을 소급하지 않는다.

### 만료·사용자 연결 삭제·공통 콘텐츠 정리 — 사용자 확정, 미구현

용어는 기존 모델에 맞춘다. **SavedItem은 사용자와 콘텐츠의 연결/개인 저장 기록**, **Content는 재사용 가능한 콘텐츠와 AI 분석(요약·카테고리 등)**이다. 사용자가 말한 아이템 삭제를 사용자 연결 삭제와 공통 콘텐츠 영구 삭제로 구분한다.

| 시점/조건 | 서버 동작 | 모바일 동작 |
| --- | --- | --- |
| 항목의 보관 만료 도달 | 자동 만료 처리. 개수 집계에서 즉시 제외. 사용자 연결과 Content는 보존 | 목록·검색·상세 등 일반 콘텐츠 화면에 만료 항목을 표시하지 않음 |
| 만료 후90일 유예 중 | 연결을 복구 가능한 상태로 보존. 제한 해제 구독 권한이 활성화되면 만료 복구 및 자동 삭제 대상 제외 | 복구된 항목을 다시 표시하고 구독에 따른 보관 권한을 설명 |
| 유예 중 복구 없이 만료 후90일 경과 | SavedItem 연결을 자동 삭제. Content와 AI 분석을 함께 삭제하지 않음 | 해당 사용자 라이브러리에 표시하지 않음 |
| Content의 사용자 연결이 전혀 없는 상태가180일 지속 | Content와 해당 AI 분석 결과 등 종속 데이터를 영구 삭제 | 해당 없음 |

- 만료 판정과 화면/집계 제외는 정리 작업이 나중에 실행되더라도 기한 기준으로 적용한다. 클라이언트 캐시에도 동일하게 반영해 만료된 내용이 남지 않게 한다.
- 만료 후 숨김은 만료 항목 목록이나 휴지통을 화면에 노출하지 않는다는 의미다. 구독 화면의 일반적인 “유예기간 내 만료된 저장 항목 복구” 설명과 항목 내용을 보여주는 것은 구분한다.
- 구독 복구는 **사용자 연결이 남아 있는 유예기간 중 항목**에 적용한다. 연결 삭제 후 Content가 남아 있어도 그 사실만으로 과거 소유 관계를 재구성하지 않는다. 사용자별 저장 기록이 삭제된 뒤의 복구는 별도 요구가 없으므로 보장하지 않는다.
- 자동 연결 삭제는 **현재 만료 시각+90일**로 통일한다. 재구독으로 실제 복구된 항목의 기존 만료/삭제 예약은 해제하고, 이후 다시 만료되면 새 만료 시각부터90일을 계산한다. 이미 만료 상태인 항목을 재조회하거나 권한 변경을 중복 처리한 것만으로 만료 시각을 갱신하지 않는다. 사용자 직접 삭제의 즉시 연결 삭제는 별도 규칙이다.
- 무연결180일은 마지막 사용자 연결이 삭제되어 연결 수가0이 된 시점부터 연속180일로 계산한다. 만료 유예 중인 연결도 실제 연결이므로 해당 시점에는 Content 정리 기간이 시작되지 않는다. 새 사용자 연결이 생기면 무연결 타이머를 해제하고, 이후 다시0이 되면 그 시점부터 다시 센다. 이 기산과 일수 기준은 DISC-010에서 확정했다.
- 연결 삭제와 Content 삭제 시 다른 사용자 참조 및 동시 저장·구독 복구를 재확인한다. 구독 권한이 활성화된 항목을 오래된 정리 작업이 삭제하지 않도록 원자적 조건 검증이 필요하다.
- 모든 기간은 개월 대신 일수로 계산한다. 무료 보관30일, 만료 후 연결 삭제 유예90일, 무연결 Content 보존180일로 확정한다. 하루는24시간 경과 기준으로 계산한다.
- 사용자 직접 삭제는 소유권 확인 후 **SavedItem 연결을 즉시 삭제**한다. 자동 만료의 삭제 유예기간을 적용하지 않고 구독 가입으로 복구하지 않는다. 공통 Content/AI 분석 결과나 다른 사용자의 연결은 삭제하지 않는다. 마지막 연결을 삭제한 경우에는 동일한 무연결 보존기간 정리 기준을 적용한다.
- 모바일은 삭제 실행 전에 **주의/확인 팝업**을 보여주고 삭제·취소 선택을 제공한다. 문구 제안: “내 보관함에서 이 항목을 삭제합니다. 삭제 후에는 구독해도 복구할 수 없습니다.” 팝업 문구는 제안이며 최종 표현은 화면 설계에서 정한다. 취소하면 서버 삭제 요청을 보내지 않고, 확정 후 서버 성공 응답을 받으면 목록·검색·개수 표시를 갱신한다. 삭제 실패를 성공으로 표시하지 않는다.
- 회원 탈퇴 시 구독 및 연결 처리의 세부 조건은 별도로 확정한다.

## 근거와 유지 방법

- [서비스 기획 초안](서비스_기획_초안.md): 핵심 저장·분석·검색 및 플랫폼 방향.
- [2차 기획](서비스_2차_기획_BM_및_장소_액션.md): 구독·보관·장소 액션 방향. 후속 확정은 이 문서에 기록하며 초기100개/30일·만료 후90일 연결 유예·무연결180일 Content 정리는 확정, 만료 전7일 안내는 미확정이다.
- [Auth 준비 점검](auth-readiness-review.md): 서버 완료 범위와 모바일·외부 연동 미검증. 재실행 Unit343/HTTP146 통과 및 이전 DB60 포함549 통과 기록을 구분한다. 이번 정리에서 테스트를 재실행하지 않았다.
- [서비스 정책](service-policy.md), [서비스 구성](service-architecture.md): 현재 구현의 기준. 미구현 MVP 계획을 이 문서들에 구현 사실로 옮기지 않는다.

구현 완료 시 각 행에 실제 Task/검증 근거를 추가하고 서버·모바일 상태를 독립 갱신한다. 사용자 결정은 결정 ID에 기록하고 정식 구현 Task 요구사항으로 연결한다.

### 만료 표시 경계

| 실제 남은 시간 | 화면 표현 | 확정 상태 |
| --- | --- | --- |
| 30일 초과 | YYYY.MM.DD 만료 | 확정 |
| 24시간 이상~30일 이하 | N일 후 만료 | 확정 |
| 1시간 이상~24시간 미만 | N시간 후 만료 | 사용자 확정 |
| 0초 초과~1시간 미만 | N분 후 만료 | 사용자 확정 |
| 0초 이하 | 항목 숨김 | 사용자 확정 |

정확히30일과24시간은 일수, 정확히1시간은 시간으로 표시한다. 표시 단위는 올림 전 실제 남은 시간으로 선택하고 숫자는 해당 단위로 올림한다. 1분 미만은 “1분 후 만료”로 표시하며 실제 만료 시각에는 항목을 숨긴다. 초기 무료30일 항목은 저장 직후부터 상대 일수 표시가 된다. 이 표시 규칙은 승인된 요구사항이다.

## 구독 상품과 상태별 정책 — 검토안

“90일”은 콘텐츠의 저장일부터 계산하는 보관 범위이며 구독 결제 주기와 별개다. 두 축 모두 충족해야 항목을 이용할 수 있도록 제안한다. 한 축의 구독만 끝나면 다른 유효 구독 권한은 유지한다. 여러 상품의 권한은 같은 축에서 더 큰 유효 권한을 적용하는 방향으로 검토하며500개+500개를1000개로 자동 합산하지 않는다.

Apple의 즉시 종료/비례 환불 문서는 Advanced Commerce API에 있으므로 일반 StoreKit 상품에도 동일하게 지원된다고 가정하지 않는다. 결제 경로/자격에 맞춰 구현 가능성을 확인한다. ### 확정 규칙과 충돌/추가 결정

- 기존 Free 한도 축소 시 이미 보관한 항목을 유지하는 승인 규칙은 **운영 정책 버전 변경**에 적용한다. 사용자 후속 요청으로 **구독 권한에 따른 개수 판정은 최신 N개 유지** 방향을 반영했다. 두 전이 규칙을 구분하고 운영 정책의 비소급 요구를 구독 종료 후 유료 혜택 유지로 해석하지 않는다.
- 이용 가능 여부와 실제 연결 삭제는분리한다. 기간/개수 만료에 따른 자동 연결 삭제는 현재 만료 시각+90일, 공통 Content 정리는 무연결180일로 확정했다.
- 앞선 “복구 후에도 기존 삭제 기한 유지” 제안은 사용자 확정으로 대체한다. 저장일·저장 순서는 유지하지만, 실제 복구 후 다시 만료되면 새로운 만료 시각+90일을 적용한다. 따라서 복구·재만료를 반복하면 연결 삭제 시점이 연장될 수 있다. 이는 사용자가 정한 복구/만료 정책의 결과이며 임의로 기존 기한을 강제하지 않는다.
- 사용자가 확정한 “영구보관”은 **구독 중에만 보관기간 제한 없음**이다. 실제 권한 종료 시 원래 저장일부터 기본30일 조건을 즉시 적용한다. 기간을 초과한 항목은 종료 시각에 만료/숨김 처리하고 종료 시각+90일에 연결을 삭제한다. 종료 후30일을 새로 부여하지 않는다. 운영 정책 변경의 기존 항목 보호 원칙은 별도로 유지한다.
- 최신순은 사용자 원래 저장 시각 기준이며 재구독 시각이나 복구 시각으로 순서를 초기화하지 않는 방향을 제안한다. 숨긴 항목을 삭제하거나 읽을 수 있도록 우회 API를 열지 않는다.
- 무제한 저장은 분석 요청 무제한과 별개다. 반복 저장/삭제에 따른 분석 요청 예산·중복 재분석 기준은 추가 설계가 필요하다.

## AI 분석 필요 여부를 먼저 판단 (승인: 2026-10-06)

카테고리를 나누기 전에 AI 분석이 필요한지를 판단한다. **구조화된 정보만으로 필요한 정보를 충분히 확보해 저장·검색할 수 있는 콘텐츠는 AI 없이 처리**한다. 지도 장소 링크가 첫 사례다. AI가 필요한 콘텐츠만 신규 AI 분석량을 사용하며, AI 없이 처리 가능한 콘텐츠는 분석량 소진 상태에서도 보관 한도 안에서 저장할 수 있다. 기존의 신규 저장 차단 제안은 AI 분석이 필요한 신규 콘텐츠에만 적용한다. 보관 한도·기간·만료·삭제 정책은 동일하게 적용한다.

판단 방향: 기존 검증된 분석 결과 재사용 가능 여부 → 구조화된 정보로 저장/검색 가능 여부 → 의미 해석이 필요한 경우 AI 분석. URL이나 제목만 있다는 이유로 충분하다고 판단하지 않는다. 비공개/삭제/접근 실패로 정보를 얻지 못한 콘텐츠를 분석 불필요 콘텐츠로 취급하지 않는다. 분석 불가/실패 항목 보존·폐기는 기존 보류 상태다.

서버(미구현): AI 필요 여부와 근거를 판정하고 구조화된 출처 정보를 추출·검증해 검색 가능한 콘텐츠를 만든다. 검증된 기존 분석 재사용 및 직접 추출 경로에서는 생성형 AI 분석량을 차감하지 않는다. 의미 기반 검색을 위한 임베딩 사용 여부/비용은 별도 설계이며 ‘AI 분석 없이’가 모든 모델/API 호출 비용0원을 뜻하지 않는다. 지원 출처·필수 정보·정보 부족 시 AI 전환 기준·정보 갱신/중복 판정은 아직 미확정이다.

모바일(미구현): 직접 정보 추출과 AI 분석의 처리 상태를 구분하고 분석 잔량 부족만으로 직접 추출 가능 저장을 차단하지 않는다. 정보가 부족한 콘텐츠를 분석 완료로 표시하지 않는다. 구체 표시 문구와 직접 추출 결과의 사용자가 수정 가능한 범위는 추후 결정한다.

사용자 결정: 사용자 직접 태그 추가는 첫 MVP에 넣지 않는다. 장소 검색 필수 목표는 부산의 고깃집 같은 지역+업종이다. 조용한/데이트 특징은 출처에서 AI 없이 확보 가능한 경우 검토하며 자동 추론이나 사용자 직접 입력을 승인한 것이 아니다.

| 단계 | 확보 가능한 정보 | 한계/처리 |

하나의 링크에서 위 단계가 함께 적용될 수 있다. 예: 블로그 본문은 직접 수집하고, 여러 장소/추천 맥락은 AI로 추출한 뒤 장소 API로 주소/업종을 검증한다. 출처의 조용한/데이트 설명을 수집할 수 있어도 객관적 특성으로 보증하지 않으며 출처 근거를 보존하는 방향을 검토한다. 단순 단어 등장만으로 태그를 확정하지 않는다. AI 없이 처리되는 콘텐츠에도 수집/API/검색 임베딩 비용이 있을 수 있다.

근거: [Open Graph](https://ogp.me/) 메타정보, [Schema.org Restaurant](https://schema.org/Restaurant) 음식 종류/메뉴 필드. 모든 사이트가 해당 필드를 제공하는 것은 아니다. [YouTube 자막 다운로드](https://developers.google.com/youtube/v3/docs/captions/download)는 권한 제약이 있어 모든 영상 자막을 공식 API로 얻는다고 가정하지 않는다. 실제 지원 사이트/수집 성공률은 후속 검증 대상이다.


사용자 후속 승인: 현재 콘텐츠 경로 비교 수준으로 기획을 기록한다. 기존 분석 재사용 → 구조화 정보 직접 수집 → 원문 수집 후 필요한 의미 해석에 AI 사용 → 접근/정보 부족 시 분석 불가로 구분한다. URL만으로 내용·업종·분위기를 확정하지 않는다. 장소 검색은 지역+업종을 필수 목표로 하고, 특징은 출처가 명시적으로 제공하는 태그가 있을 때만 검토한다. 사용자 직접 태그 추가는 제외한다. 지원 사이트별 구현 가능성/수집 성공률을 검증한 결과나 제품 구현 완료를 의미하지 않는다.

## 지원 콘텐츠·검색 구성 확정 (2026-10-06)

지원 대상으로 지도, SNS, 유튜브, 상품 링크, 블로그, 일반 웹, 뉴스와 사용자 예시의 PDF 문서·이미지 공유·GitHub 저장소를 기록한다. 1차 분류는 URL 주소/경로를 이용한다. 이미지 공유는 URL이 없는 직접 이미지 입력도 구분한다. 기존 이미지/OCR 제외 표현 중 이미지 공유 입력은 이번 요청으로 지원 대상으로 변경하되 OCR/영상 전사 범위까지 확정하지 않는다.

자연어 검색은 사용자 지정 **multilingual-e5-small + PostgreSQL pgvector** 연동을 사용한다. 기존 OpenAI 임베딩 단가 예시는 이 선택의 실제 검색 원가가 아니며 자체 모델 실행 비용/자원은 후속 측정한다. 검색 파라미터·색인·질의/문서 전처리·품질 검증 기준은 구현 설계 시 구체화한다. 분석 실패 처리 및 출시 기준은 보류한다. 구독 상세 설계 보류 유지.

공유 예외는 질문을 통해 순차 확정한다. 현재 첫 질문은 오프라인 공유 시 즉시 실패할지 기기 임시 보관 후 재전송할지다. 중복 저장, 로그인 후 공유 재개, 재시도 총/추가 횟수와 간격도 아직 미확정이다.

## 시도 횟수 의미 확정

사용자 선택: 모바일 업로드3회·서버 작업 등록5회·작업 실행3회는 모두 최초 시도를 포함한 총 횟수다. 따라서 추가 재시도는 각각 최대2회/4회/2회다. 각 구간의 횟수는 독립적으로 집계하고, 같은 작업의 재시도로 중복 저장이나 분석량 중복 차감이 발생하지 않도록 한다. 총 시도 한도까지 실패한 경우 각 구간의 기존 실패 안내 정책을 따른다. 모바일2초 간격은 기존 요구이며 고정 간격/지수 backoff 의미와 서버 구간 간격은 아직 미확정이다. 분석 최종 실패 항목 보존/폐기는 계속 보류한다. 제품 구현 완료를 뜻하지 않는다.

## 모바일 업로드 재시도 간격 확정

사용자 선택: 모바일 업로드는 최초 포함 총3회, 추가 재시도2회이며 지수 backoff를 사용한다. 첫 실패 후2초 대기하여 두 번째 시도, 두 번째 실패 후4초 대기하여 세 번째 시도한다. 대기 시간은 이전 시도의 실패가 확정된 시점부터 계산하며 각 요청 수행 시간과 별개다. 세 번째 실패 시 저장 실패를 안내한다. 처음부터 오프라인인 경우는 기존 정책대로 즉시 실패하고 저장/자동 재전송하지 않는다. 서버 작업 등록 총5회와 작업 실행 총3회의 대기 간격은 아직 확정하지 않았다. 제품 구현 완료를 뜻하지 않는다.


## 구간별 재시도 최종 확정

사용자 승인: 서버도 지수 backoff를 적용한다. 최초 시도를 포함한 총 횟수이며 대기는 이전 시도 실패 확정 후 시작한다. 각 요청/작업의 수행 시간은 대기 시간과 별개다.

| 구간 | 총 시도 횟수 | 최대 추가 재시도 | 실패 후 대기 |
| --- | ---: | ---: | --- |
| 모바일 업로드 | 3회 | 2회 | 2초 → 4초 |
| 서버 작업 등록 | 5회 | 4회 | 2초 → 4초 → 8초 → 16초 |
| 서버 작업 실행 | 3회 | 2회 | 2초 → 4초 |

이 표가 과거 횟수/간격 미확정 기록을 대체한다. 같은 요청/작업 재시도는 중복 저장·중복 분석량 차감을 막아야 한다. 최초 오프라인 공유는 즉시 실패·저장 없음으로 처리한다. 최종 분석 실패 시 알림 요구는 유지하되 실패 항목의 보존/폐기는 사용자 보류 상태다. 구간별 timeout·재시도 대상 오류·작업 등록 영속성/복구 계약은 구현 설계 때 구체화한다. 제품 코드에 적용/검증된 것이 아닌 확정 기획이다.


## 사용자별 재저장 시 날짜 갱신 확정

사용자 결정: 사용자가 현재 보관 중인 같은 콘텐츠를 다시 공유/저장하면 기존 사용자 저장 연결을 유지하고 저장일과 만료일을 갱신한다. 중복 항목을 추가하지 않는다. 보관 중복 판정은 전체 공통 콘텐츠 등록 여부가 아닌 해당 사용자의 보관 여부 기준이다. 이전 저장일/만료일 유지 제안은 폐기한다.

저장일은 명시적으로 재저장이 성공한 시점으로 갱신하고 만료일도 이에 맞춰 적용 보관기간으로 재산정하는 방향이다. 같은 요청의 통신 재시도/중복 전달은 새 사용자 재저장으로 취급하지 않아야 한다. 갱신된 저장일은 최신 보관 순서에 영향을 준다. 유효한 기존 분석 결과를 재사용하는 경우 AI 재분석을 요구하지 않는다.

재저장 시 원래 저장 정책 스냅샷 유지/현행 정책 적용 여부, 보관 한도 도달 상태에서 기존 항목 날짜 갱신 허용, 만료되어 숨겨졌으나90일 유예로 연결이 남은 항목의 재저장/복구 및 새 만료·삭제 일정은 후속 확정 대상이다. 구독 상세 보류를 해제한 결정이 아니다. 제품 구현 완료를 뜻하지 않는다.


## 재저장 시 현행 정책 적용 확정

사용자 선택: 본인이 보관 중인 동일 콘텐츠를 명시적으로 다시 저장하면 재저장 시점의 새 정책을 적용한다. 기존 사용자 저장 연결의 정책 버전/조건 스냅샷을 현행 정책으로 갱신하고 저장일·만료일을 재산정한다. 기존 정책 버전 자체를 수정하지는 않는다. 다시 저장하지 않은 기존 항목은 이전 정책을 유지하므로 일괄 소급 적용과 구분한다. 사용자의 재저장이 성공한 시점을 기준으로 적용하며 같은 요청의 통신 재시도/중복 전달은 별도 재저장으로 취급하지 않는다.

모바일은 갱신된 저장일·만료일·적용 정책을 명확하게 표시한다. 자동 갱신/이전 정책 유지 선택 기능은 이번 승인 범위가 아니다. 만료되어 숨김 상태지만 연결 삭제 유예 중인 항목의 재저장/복구, 보관 한도 도달 상태에서 재저장 허용 여부는 후속 결정이다. 구독 시스템 상세 설계 보류는 유지한다. 제품 구현 완료를 뜻하지 않는다.


## 만료 유예 항목 재저장 복구 확정

사용자 승인: 만료되어 화면/검색에서 숨겨졌으나 만료 후90일 삭제 유예로 사용자 연결이 남아 있는 콘텐츠를 다시 공유/저장하면, 현재 활성 보관 수가 한도 미만인 경우 기존 연결을 복구한다. 복구 성공 시 저장일을 재저장 시점으로 갱신하고 현행 정책 버전/조건을 적용해 만료일을 재산정한다. 이전 만료의 연결 삭제 예약을 취소하고 화면/검색에 다시 표시한다. 복구된 항목은 활성 보관 수에 포함한다.

보관 한도가 가득 찬 경우 복구/저장을 차단하고 한도 안내를 표시한다. 실패한 복구는 날짜/정책/기존 삭제 예약을 변경하지 않는다. 같은 요청의 중복 전달로 복구/날짜 갱신/분석량 차감이 반복되지 않도록 한다. 유효한 기존 분석은 재사용한다. 이후 다시 만료되면 새 만료 시각+90일에 연결을 삭제한다.

이미 연결이 삭제된 항목의 새 저장은 기존 연결 복구와 별개다. 사용자 직접 삭제된 연결은 구독/자동 복구로 되살리지 않는 기존 정책을 유지한다. 미만료 항목 재저장을 보관 한도 도달 상태에서도 허용할지는 아직 별도 결정 대상이다. 구독 상세/분석 실패 데이터 처리/출시 기준 보류 유지. 제품 구현 완료를 뜻하지 않는다.
