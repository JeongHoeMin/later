# Requirement

## R1 · 공유 요청 제한
- AC-R1-1: 로그인·Apple/Naver 시작·Naver callback은 IP별 공유 60초 20회, refresh와 logout은 각각 IP별 60회, 연동·연동 시작은 IP별 및 인증 회원별 각각 10회로 제한한다. 허용 횟수 다음 요청부터 429/RATE_LIMIT_EXCEEDED와 Retry-After 초를 반환한다.
- AC-R1-2: IP 검사→회원 인증→회원 검사 순서로 수행하고 차단된 요청은 입력 소비/외부 인증/세션 변경을 하지 않는다. 오류/입력 실패도 횟수를 소비하고, 차단 요청은 창을 연장하지 않는다. 읽기·탈퇴·비인증 경로는 이번 대상이 아니다.
- AC-R1-3: PostgreSQL 원자적 증가로 인스턴스 간 공유한다. 60초는 첫 요청부터이며 DB 시각을 사용한다. 만료 경계에서는 새 창이 시작된다. 토큰/원본 IP/회원 ID를 저장하지 않고 SHA-256 키와 집계만 저장한다. 저장소 장애는 요청을 실패시킨다.
## R2 · 운영과 문서
- AC-R2-1: 전달 IP 헤더는 기본 신뢰하지 않는다. 명시한 TRUSTED_PROXY_CIDRS만 신뢰하며 잘못된 설정은 시작 시 거부한다. IPv4 mapped/IPv6 표기를 정규화한다.
- AC-R2-2: 만료 카운터는 기존 정리 주기에 최대 500개 정리하고 migration은 새 테이블·인덱스만 생성한다. 429 OpenAPI 및 서비스 정책 문서를 갱신한다.
## Out of Scope
Redis 설치, 모바일/운영 배포, 비인증 전체 트래픽 제한, 제공자 계정 잠금, CAPTCHA, 운영 수치 튜닝.

## Service Policy Impact

[서비스 정책](../../../docs/service-policy.md)의 인증 요청 제한, 카운터 보존·정리 및 프록시 적용 항목을 추가한다. 로그인·탈퇴·연동의 기존 규칙을 변경하지 않는다.
