# Requirement

## Background / Goal

구글·카카오 소셜 로그인에 네이버를 추가한다. 자체 비밀번호 회원가입은 없다.
사용자는 2026-10-02 이 Task 문서 작성만 요청했다. 기능 구현은 다른 세션에서 승인 후 수행한다.
기준 브랜치: feat/auth. 카카오 구현 커밋: 8e0af89. 이 문서는 실행 계획의 초안이며 외부 인증 계약 확인 전 인증 방식을 확정하지 않는다.

## R1 - 네이버 서버 인증

- AC-R1-1: 네이버가 검증한 사용자 식별자로 회원을 연결한다. 클라이언트가 보낸 subject나 이메일만으로 인증하지 않는다.
- AC-R1-2: 선택한 인증 방식으로 우리 앱에 발급된 인증 정보임을 확인한다. 단순 프로필 조회가 앱 귀속까지 증명한다고 가정하지 않는다.
- AC-R1-3: 잘못된·만료된 인증 정보와 외부 서버 장애·통신 실패·타임아웃을 구분한다. 실패 시 회원과 세션을 처리하지 않는다.

## R2 - 설정과 의존성 연결

- AC-R2-1: 공식 계약에 필요한 설정을 확인하고 누락·잘못된 설정을 모듈 구성 시 검증한다. 비밀 정보는 저장소에 남기지 않는다.
- AC-R2-2: SocialAuthProvider 구현을 AuthModule에 등록하고 검증된 (naver, subject)를 기존 회원 연결 흐름에 전달한다. 구글·카카오 동작을 유지한다.

## R3 - 기존 HTTP 로그인 확장

- AC-R3-1: POST /auth/social/login에서 naver를 지원하고 검증된 신규·기존 회원에게 기존 형식의 서비스 토큰과 세션을 발급한다.
- AC-R3-2: 입력 오류·인증 실패·외부 장애는 공통 오류 계약을 따르며 원문 credential과 외부 내부 내용을 노출하지 않는다.

## Out of Scope

모바일 로그인 화면·SDK, 프로필 수집, 이메일 기반 자동 계정 통합, 네이버 토큰 갱신·연결 해제, DB 스키마 변경, auth PR/push/병합.
인가 코드 교환이나 HTTP 입력 변경이 필요한지는 공식 계약을 확인한 뒤 제안하고 승인받는다.
